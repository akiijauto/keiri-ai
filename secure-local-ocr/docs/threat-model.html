1. 前提

1.1 守る資産

資産内容漏えい時の影響
A1 撮影画像お客様が記入した書類そのもの記載された全情報が流出。筆跡・押印も含む
A2 OCR結果書類の全文テキストA1とほぼ同等
A3 抽出項目氏名・住所・生年月日・電話番号など名寄せ可能な個人情報の流出
A4 監査ログ操作の記録設計上、値を含まないため影響は限定的
A5 セッション鍵引き渡しの完全性検証用単独では価値が低い（端末内限定・短命）
A6 業務Webの認証情報登録先へのログインなりすまし登録。本システムは保持しない

1.2 想定する攻撃者

ID攻撃者動機能力
AT1端末を拾った第三者金銭・愉快犯端末の物理的所持。ロック解除は不可
AT2同一Wi-Fi上の攻撃者情報窃取通信の傍受・中間者攻撃
AT3悪意あるWebサイト個人情報の窃取利用者を誘導してページを開かせる
AT4端末上の別アプリ情報窃取クリップボード監視、スクリーン録画、ストレージ探索
AT5正規利用者の不注意悪意なし誤入力、誤送信、画面の放置
AT6内部の悪意ある利用者情報持ち出し正規の認証を持つ
AT7クラウド事業者・SDK提供者—送られたデータを見得る立場
AT8開発者の実装ミス悪意なし設計意図から外れたコードの混入

1.3 対象外とする脅威

  • 端末OSそのものの脆弱性・ゼロデイ（OS更新とMDMで対応する領域）
  • 紙資料そのものの管理（本システムの範囲外）
  • 登録先Webシステム側の脆弱性（別システムの責任範囲。ただし連携方法は本書で規定）
  • 物理的な盗み見（ショルダーハック）。運用ルールで対応

2. 脅威一覧と対策

STRIDEの観点で、本システムに固有のものを挙げます。

T1: OCR対象がクラウドへ送信される（情報漏えい／AT7）

攻撃経路クラウドOCR APIの利用、OCRエンジンの内部通信、モデルの遅延ダウンロード、解析SDK
影響A1・A2が第三者の管理下へ。本システムの存在意義が失われる
対策 ・OCRは端末内モデルのみ（Android: 同梱モデル／iOS: requiresOnDeviceRecognition = true）
・offline フレーバーは INTERNET 権限を持たない
・解析SDK・広告SDK・クラッシュレポータを依存に含めない
・APKの権限をビルドのたびに機械検証
残存リスク OCRエンジンの内部動作は監査できない。実端末での通信監視（未実施）で確認する必要がある 要実測

T2: 個人情報が生成AIへ送信される（情報漏えい／AT7）

攻撃経路「項目抽出を賢くしたい」という理由でのAPI利用。開発時のデバッグでの投入
影響A2・A3が第三者の学習データ・ログへ
対策 ・項目抽出は決定的なルールベース処理。AIを使わない
・生成AIのSDK・クライアントを依存に含めない
・テストデータはすべて架空（protocol/testdata/）
・原則2として文書化し、拡張時も基本設計から分離する
残存リスク将来の機能追加で持ち込まれる可能性。依存追加時のレビュー観点として明記

T3: 悪意あるWebページが値を受け取る（なりすまし／AT3）

攻撃経路利用者を偽サイトへ誘導し、ブリッジのハンドシェイクに応答して値を受け取る
影響A3が攻撃者のサーバへ
対策 ・アプリ側でWebViewのオリジンを許可リスト検証。一致しなければ値を渡さない
・iOSは許可リスト外のURLへの遷移自体を拒否
・ページ側も allowedHostOrigins で別オリジンからのメッセージを破棄
・拒否時は理由を返さず、監査ログに ORIGIN_DENIED だけ残す
検証E2E済 別オリジンからの引き渡しで入力欄が空のままであることを確認
残存リスク許可リストに登録したドメインが乗っ取られた場合は防げない

T4: 引き渡しデータの改ざん・リプレイ（改ざん／AT4）

攻撃経路端末内の別経路からの値の差し替え、過去のEnvelopeの再投入
影響誤った内容での登録。別人の情報の混入
対策 ・HMAC-SHA256（セッション鍵は端末内生成・端末外へ出さない）
・失効時刻（既定5分・上限15分）
・nonce の単回消費
・handoff_id の重複拒否
・受け取り側での正規化の再計算
検証E2E済 失効・改ざんの両方で拒否されることを確認

T5: 端末の紛失・盗難（情報漏えい／AT1）

攻撃経路端末の物理的取得後のアプリ起動、ストレージの探索
影響ディスク上に個人情報があれば流出
対策 ・個人情報をディスクに保存しない（最大の対策）
・起動時に生体認証／画面ロック認証
・3分経過で値を破棄して再認証
・クラウドバックアップ・端末間転送を禁止
・画面ロック未設定の端末では利用させない
残存リスクアプリ起動中に奪われた場合は画面の内容が見える。再認証の猶予を短くする以外に手はない

T6: 端末上の別アプリによる窃取（情報漏えい／AT4）

攻撃経路クリップボード監視、画面録画、アプリ専用領域への侵入（Root化時）
影響A3が同一端末上の別アプリへ
対策 ・Android: FLAG_SECURE でスクリーンショット・録画を抑止
・クリップボードに機微フラグ（iOSは端末内限定＋60秒失効）
・Root化の簡易検出
・アプリ専用領域のみ使用。外部ストレージを使わない
残存リスク iOSではスクリーンショットを防げない。 Root化検出も回避可能。業務専用端末＋MDMが本命の対策

T7: 通信の傍受・中間者攻撃（情報漏えい／AT2）

攻撃経路公衆Wi-Fi上での傍受、偽アクセスポイント、証明書の偽装
影響Web登録フェーズの通信内容の窃取
対策 ・OCRフェーズはそもそも通信しない（傍受する対象が無い）
・平文通信の全面禁止（Android: networkSecurityConfig／iOS: ATS）
・通信先を許可リストのドメインに限定
残存リスク証明書ピンニングは未実装。Phase 4で対象サイトの構成を調査のうえ検討する

T8: 誤認識のまま登録される（完全性／AT5）

攻撃経路攻撃ではなく事故。OCRの誤読、項目の取り違え、確認の形骸化
影響誤った個人情報での登録。別人の情報の混入
対策 ・確認チェックを付けた項目だけが引き渡し対象（INV-1）
・信頼度が低い項目・検証に落ちた項目を警告表示
・読み取った生の文字列も併記し、人間が突き合わせられるようにする
・必須項目の不足を検出
・登録先で入力欄を埋めたあと、送信は人間が押す（INV-4）
・自動推定で埋めた欄は色を変えて区別
残存リスク 確認作業が形骸化すれば効果は落ちる。 「全項目一括確認」ボタンを目立たせない、といったUI上の配慮を継続する

T9: 個人情報がログに残る（情報漏えい／AT8）

攻撃経路デバッグ用のログ出力の消し忘れ、例外メッセージへの値の混入
影響ログの持ち出し・共有により個人情報が流出
対策 ・監査ログは属性キーを許可リスト方式にし、値を実行時検査
・例外は種別コードのみを扱い、メッセージ本文を運ばない
・3実装すべてに同じ検査。自動テストで確認
・Androidのデバッグビルドでは StrictMode でディスク書き込み・通信を検出
検証自動テスト済 氏名・電話番号・メール・カナを渡すと例外になることを確認

T10: 実装の版ずれによる誤判定（完全性／AT8）

攻撃経路取込元と登録先で共有コアの版が食い違い、片方が正しいとした値をもう片方が別解釈する
影響誤った値での登録。あるいは正常な引き渡しの不能
対策 ・受け取り側で正規化を再計算し、届いた値と一致しなければ拒否（INV-6）
・3実装が同じテストベクタを読む
・Profileを版番号付きで管理し、Envelopeに版を含める
残存リスク版が上がったときの移行期間の設計は未着手。Profile v2 を作る前に決める

T11: 内部利用者による持ち出し（情報漏えい／AT6）

攻撃経路正規の認証を持つ利用者が、画面を撮影する・クリップボード経由で持ち出す
影響A3の流出
対策 ・監査ログにいつ何件処理したかを記録（値は含まない）
・スクリーンショット抑止（Androidのみ）
・クリップボードの制限
残存リスク 技術的にはほぼ防げない。別のカメラで画面を撮れば済む。 監査ログによる事後追跡と、業務専用端末での運用が現実的な対策

3. 対策の優先度

脅威発生可能性影響優先度状態
T1 クラウドへの送信中致命的最高対策済／実測待ち
T2 生成AIへの送信中致命的最高対策済
T8 誤認識のまま登録高大高対策済
T5 端末紛失中大高対策済
T3 悪意あるページ低大高対策済・検証済
T9 ログへの混入中中中対策済・検証済
T4 改ざん・リプレイ低中中対策済・検証済
T6 別アプリによる窃取低中中iOSは限定的
T7 通信の傍受低中中対策済
T10 実装の版ずれ中中中対策済
T11 内部持ち出し低大低（技術的に）運用に依存

4. 更新の方針

本書は以下のときに見直します。

  • 依存ライブラリを追加・更新したとき（T1・T9の再評価）
  • 新しい取込元・受け渡し手段を追加するとき（T3・T4の再評価）
  • 保存要件が発生したとき（T5の前提が変わる）
  • 対象Webサイトを追加するとき（T3・T7の許可リスト再評価）
  • 実端末での通信監視を実施したとき（T1の残存リスクを更新）
