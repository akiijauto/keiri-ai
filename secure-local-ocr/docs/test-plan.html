1. 方針

機能テストだけでは合格としません。 とくにネットワークについては「コード上では通信していない」を根拠にしない という企画書の方針に従い、成果物と実端末で実測します。

層対象頻度自動化
L1 単体正規化・抽出・Envelope・監査ログ毎コミット済
L2 実装間一致Kotlin / JavaScript / Swift の判定一致毎コミット済
L3 成果物検証APKの権限・設定毎ビルド済
L4 ブラウザE2E引き渡しから充填、拒否条件毎コミット済
L5 実端末機能OCR精度・速度・操作性リリース前手動
L6 実端末セキュリティ通信監視・データ残存リリース前手動

5.1 準備

  • Android実端末（Android 8.0以上）
  • 試験用帳票。架空データのみを印字した入居申込書を用意する
  • 照明条件の異なる場所（明るい室内・薄暗い室内・蛍光灯の反射がある場所）

5.2 試験項目

#項目手順合格条件
M-01オフラインでの完走機内モードで 撮影→OCR→抽出→確認 まで操作すべて完了できる
M-02必須項目の抽出正対・明るい環境で撮影必須6項目が抽出され、修正不要または軽微な修正で済む
M-03処理速度撮影ボタンから結果表示までを計測（5回）平均3秒以内
M-04傾き耐性15度・30度傾けて撮影15度で必須項目が取れる。30度は要確認扱いでよい
M-05暗所薄暗い環境で撮影読めない場合、誤った値を確定させず「要修正」になる
M-06反射光沢紙・蛍光灯下で撮影同上
M-07小さい文字8pt程度の文字を含む帳票読めない場合に誤読を確定させない
M-08修正操作誤認識された項目を手で直すその場で再検証され、確認チェックが付けられる
M-09必須不足の検出一部項目を隠して撮影不足項目が警告され、先へ進めない
M-10Web入力支援参照実装（10.0.2.2:8787）へ引き渡す入力欄が埋まり、自動送信されない
M-11再認証確認画面で3分以上放置してから戻る値が破棄され、認証からやり直しになる
M-12スクリーンショット確認画面でスクリーンショットを試みる撮影できない（Android）

6. L6: 実端末でのセキュリティテスト（未実施）

6.1 通信監視（最重要）

企画書20の合格条件そのものです。手順は tools/verify_no_network.sh も表示します。

手順A: 機内モードでの機能確認

  1. 端末を機内モードにする
  2. 撮影 → OCR → 項目抽出 → 確認 まで操作する
  3. 合格条件: すべて完了できる

手順B: 経路での捕捉（証跡を残す）

  1. 検証用PCでアクセスポイントを立て、端末を接続する
  2. 捕捉を開始する 
    sudo tcpdump -i <interface> -w ocr_phase.pcap host <端末のIP>
  3. 撮影 → OCR → 確認 まで操作する（Web入力へは進まない）
  4. 捕捉を停止し、解析する 
    python3 tools/analyze_pcap.py ocr_phase.pcap --phase ocr
  5. 合格条件: 「合格」と表示され、端末外への宛先が0件

手順C: Web登録フェーズの許可リスト確認

  1. 同じ手順で捕捉しながら、Web入力まで進める
  2. 解析する 
    python3 tools/analyze_pcap.py web_phase.pcap --phase web --allow <業務サイトのIP>
  3. 合格条件: 業務サイト以外の宛先が0件

analyze_pcap.py は合成pcap3種（ループバックのみ／外部送信あり／許可先のみ）で 動作確認済みです。外部送信ありのケースで終了コード1を返すことを確認しています。

8. 回帰テストの運用

変更内容再実行するもの
正規化・抽出の規則を変えたL1・L2 の全実装（3言語すべて）
プロトコルを変えたL1・L2・L4。ベクタの再生成が必要な場合あり
依存ライブラリを追加・更新したL3を必ず。加えてL6の通信監視
ブリッジ・登録先ページを変えたL4
カメラ・OCR周りを変えたL5・L6
UIの文言だけ変えたL1・L4（回帰確認）
テストベクタが落ちたときの原則。 共通ベクタは3実装の一致を保証するためのものです。 片方だけ落ちたら、実装が仕様から外れたということです。 ベクタを緩めて通すことはしません。実装を直してください。
