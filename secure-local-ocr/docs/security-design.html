1. 方針

本システムは「守るための機能を足す」のではなく、 危険なことができない構造にすることを優先します。 実行時のチェックはすり抜けますが、権限を持たないビルドはすり抜けません。

強さ手段本システムでの例
強OSが強制するINTERNET権限を持たないビルド。FLAG_SECURE。バックアップ除外
中ビルド時に機械検証するAPKの権限検査タスク。共通ベクタによる実装一致の検証
中実行時に必ず通る経路で弾くEnvelope検証。監査ログの値検査
弱実装者が気をつける（これに頼る設計を避ける）

3. ネットワーク分離

3.1 権限による分離（Android）

offline フレーバーは INTERNET 権限を持ちません。 アプリのコードがソケットを開こうとしても、OSが拒否します。

実際に起きたこと。 権限を宣言しないだけでは足りませんでした。ML Kit が依存するライブラリのマニフェストから INTERNET が自動的に取り込まれていたためです。 tools:node="remove" で明示的に除去し、 ビルドのたびに実APKを検査するタスクを追加しました。詳細は 振り返り の課題1。

3.2 通信先の許可リスト

層を重ねているのは、1つが破られても残りが効くようにするためです。 ブラウザE2Eでは、別オリジンのページからの引き渡しが ORIGIN_DENIED として捨てられ、入力欄が空のままであることを確認しています。

4. 引き渡しの完全性

受け取り側は、以下をすべて確認してから充填します。1つでも落ちたら値を1文字も入れません。

検査防ぐもの拒否コード
オリジン許可リスト悪意あるページへの値の流出E_ORIGIN
プロトコル・Profile一致版の食い違いによる誤解釈E_PROTOCOL
confirmed フラグ未確認データの混入E_UNCONFIRMED
失効時刻古いEnvelopeの使い回しE_EXPIRED
nonce の一致・単回消費ハンドシェイクの横取りE_NONCE
handoff_id の重複同じEnvelopeの再投入E_REPLAY
正規化の再計算正規形でない値・実装の版ずれE_VALIDATION
HMAC-SHA256途中での改ざん・取り違えE_INTEGRITY

4.1 HMACの位置づけ

セッション鍵は端末内で生成され、端末外へ出ません。 目的は秘匿ではなく、同一端末内での取り違え・改ざん・リプレイの検知です。 秘匿は「受け渡しが端末内で完結している」ことそのものが担保します。

署名対象は正準化JSON（キーをUTF-16コードユニット順にソートし、空白なしで直列化したもの）です。 3実装でバイト単位に一致させる必要があり、 数値の表現（1.0 か 1 か）まで規則で固定しています。

6. 監査ログ

ログには「何が起きたか」だけを書き、「何が書かれていたか」は書きません。 方針として掲げるだけでは守られないので、実行時に検査します。

  • 属性キーは許可リスト方式。name や value といったキーは受け付けない
  • 属性値は、個人情報らしきパターン（7桁以上の連続数字・メールアドレス形式・ 漢字の氏名らしき並び・4文字以上のかな）に一致したら例外にする
  • 例外が出たら、その行は記録せず「記録を拒否した」という事実だけを残す

Kotlin・Swift・JavaScriptの3実装すべてに同じ検査を入れ、自動テストで確認しています。

記録される内容の例

2026-08-22T07:11:41Z    HANDOFF_REQUESTED   document_type=residency_application fields=8
2026-08-22T07:11:41Z    HANDOFF_DELIVERED   fields=8 handoff_id=14910608…
2026-08-22T07:11:41Z    HANDOFF_VERIFIED    result=ok fields=8
2026-08-22T07:11:41Z    FORM_FILLED         filled=8 skipped=0 guessed=0
2026-08-22T07:12:03Z    SUBMIT_BY_HUMAN     document_type=residency_application

誰の何を扱ったかは分かりませんが、いつ何件処理したかは追えます。監査の目的には足ります。

7. 依存関係の方針

依存ライブラリは、コードだけでなく権限・通信・マニフェスト設定を持ち込みます。 実際にそれで通信権限が混入しました。

方針理由
解析SDK・広告SDK・クラッシュレポータを入れない個人情報を扱う画面から外部へ情報が出る経路になる
JSONライブラリを使わず自前実装依存削減と、正準化を3実装で完全一致させる必要
OCRモデルはAPK同梱モデル取得のための通信を発生させない
Webは依存パッケージ0ブリッジは登録先サイトへ配布するもの。持ち込む依存を無くす
依存追加時はAPKの権限を再検査するビルドタスクで自動化済み

8. 現時点の限界

限界影響補い方
iOSでスクリーンショットを防げない画面を撮影されれば個人情報が流出するMDMでの制限。運用ルール
Root化検出は回避可能改造端末での利用を完全には止められない業務専用端末＋MDM
OCRエンジン自体は監査できないML Kit / Vision の内部動作は検証できない通信監視で外部送信がないことを実測する
WebViewのJSコンテキストに値が渡る登録先ページの実装不備があれば影響を受けるオリジン許可リスト。マッピング定義の管理
実端末での通信監視が未実施原則8をまだ満たしていないテスト計画 の手順を実行する

限界を隠さず書くのは、運用側が判断できるようにするためです。 「アプリが守るので大丈夫」と言えない部分は、はっきりそう書きます。
