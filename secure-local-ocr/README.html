Secure Local OCR

完全オンデバイスOCR入力支援システム ／ 開発環境構築・ビルド・テスト・運用手順
要件定義 振り返り アーキテクチャ セキュリティ設計 脅威モデル テスト計画 タブレット実機確認

これは何か

個人情報を含む紙資料を、スマートフォン／タブレットの端末内だけでOCRし、 人間が確認した項目だけを業務Webサイトへ入力する仕組みです。 OCR対象の画像もOCR結果も、クラウドOCRにも生成AIにも送りません。

本リポジトリには別企画（請求書仕訳AI）も含まれています。 本システムは secure-local-ocr/ 配下で完結しており、 リポジトリ直下の api/ app/ 要件定義.md などとは コードもデータも設定も共有しません。混同しないでください。

ビルドと実行

1. 共有コア（Kotlin）のテスト

Android SDK が無い環境でも実行できます。業務ロジックの検証はここが中心です。

cd secure-local-ocr/android
gradle :core:test

2. Androidアプリ

export ANDROID_HOME=/path/to/android-sdk

cd secure-local-ocr/android

# 通信を一切行わないビルド（OCR専用・INTERNET権限なし）
gradle :app:assembleOfflineDebug

# Web入力支援まで行うビルド
gradle :app:assembleWebDebug

# offline ビルドに通信権限が混入していないことを検証（ビルドも自動で走ります）
gradle :app:verifyOfflineFlavorHasNoInternet

生成物は android/app/build/outputs/apk/<flavor>/debug/ に出ます。

adb install -r app/build/outputs/apk/offline/debug/app-offline-debug.apk
verifyOfflineFlavorHasNoInternet は飾りではありません。 依存ライブラリのマニフェストから INTERNET 権限が実際に混入した経緯が 振り返り にあります。ビルドのたびに実行してください。

3. Web（登録先サイトと入居フォーム）

cd secure-local-ocr/web
node server.mjs                       # http://127.0.0.1:8787/
node server.mjs 8787 192.168.1.10     # 実機検証時のみ: 同じWi-Fi上のタブレットから繋ぐ

# 共有コア（JS）のベクタテスト
npm test

# ブラウザE2E（Playwrightが必要）
npm i -D playwright
npm run test:e2e

ブラウザで開く画面：

  • http://127.0.0.1:8787/ — 説明と入口
  • http://127.0.0.1:8787/intake/ — 入居フォーム（Web入力の取込元）
  • http://127.0.0.1:8787/registration/ — 登録先の申込フォーム

4. 実機（Androidタブレット）で確認する

APKはCIがビルドし、Releaseから直接ダウンロードできます（リポジトリは非公開のため、 タブレットのブラウザでGitHubにログインしてください）。 手順は タブレット実機確認の手順 にまとめています。 検証用紙は samples/test-form-01.pdf / test-form-02.pdf、 期待値は samples/expected-values.html です。

タブレット単体で、OCR精度・処理速度・機内モードでの完走・ 「通信権限を持たないこと」まで確認できます。 Webフォームへの充填だけは、同じWi-Fi上のPCで参照実装を動かす必要があります。

5. iOS / iPadOS

cd secure-local-ocr/ios/SloCore
swift test                            # 共有コアのベクタテスト

cd ..
brew install xcodegen
xcodegen generate
open SecureLocalOcr.xcodeproj

現時点で Swift のビルドとテストは未実行です（開発環境がLinuxのため）。 詳細は ios/README.md を参照してください。

動かしてみる（Web連携の確認）

  1. node server.mjs でサーバを起動する
  2. http://127.0.0.1:8787/intake/ を開く
  3. 架空データを入力する。たとえば氏名「山田 太郎」、生年月日「昭和55年1月1日」、 郵便番号「〒150-0001」、電話「090-1234-5678」
  4. 入力するそばから正規化結果が表示される（半角カナ→全角、和暦→西暦、など）
  5. 「確認して登録先へ引き渡す」を押す。登録先の画面が開く
  6. 入力欄が自動で埋まる。生年月日は 1980/01/01、郵便番号と電話番号は 登録先の欄割りに合わせて分割される
  7. 送信ボタンは押されない。内容を確認して自分で押す
  8. 画面下の監査ログに値が一切出ていないことを確認する

アプリからの引き渡しも同じ経路です。Androidエミュレータからホストの参照実装へ繋ぐ場合は http://10.0.2.2:8787/registration/ を対象URLに設定してください。

テストベクタを変更したとき

protocol/testdata/ は3実装が共有します。 片方だけ通ってもう片方が落ちたら、実装のどちらかが仕様から外れたということです。 ベクタを緩めて通すのではなく、実装を直してください。

正準化/HMACのベクタは生成物です。仕様を変えたときだけ再生成します。

python3 tools/gen_canonical_vectors.py

登録先サイトへの組み込み方

登録先の業務Webサイト側で必要なのは、次の2つだけです。

1. マッピング定義を用意する

{
  "site": "example-residency",
  "document_type": "residency_application",
  "map": {
    "name":        { "selector": "#applicant_name" },
    "birthday":    { "selector": "#birth", "format": "YYYY/MM/DD" },
    "postal_code": { "selector": ["#zip1", "#zip2"], "split": "-" },
    "phone":       { "selector": ["#tel1","#tel2","#tel3"], "split": "jp-phone" }
  }
}

2. ブリッジを読み込む

import { installBridge } from '/slo/slo-bridge.js';

const mapping = await fetch('/slo/mapping.json').then(r => r.json());
const bridge = installBridge({
  documentType: mapping.document_type,
  mapping,
  allowedHostOrigins: [window.location.origin],
  onFilled: ({ filled, guessed }) => { /* 画面に知らせる */ },
  onRejected: (code) => { /* 理由コードを表示する */ },
});

document.getElementById('btn-ready').addEventListener('click', () => bridge.ready());

これでOCRアプリからもWeb入力からも受け取れます。 ブリッジは入力欄を埋めるところまでしか行わず、送信は行いません。

ページのCSPを script-src 'self' にする場合、 インラインの <script> は動きません。 ページ用のスクリプトも外部ファイルにしてください（実際にこれで詰まりました）。

配布と運用

配布

  • 業務専用端末にMDM経由で配布する。一般公開ストアでの配布は想定しない
  • リリースビルドは gradle :app:assembleWebRelease（署名設定は各組織の鍵で行う）
  • OCR専用運用（Web入力を行わない現場）では offline フレーバーを配布する

MDMで制御すべき項目

  • クラウド同期（写真・バックアップ）の禁止
  • USBデータ転送の禁止
  • スクリーンショットの禁止（特にiOSはアプリ側で防げないため必須）
  • クリップボード共有の制限
  • アプリの追加インストール制限

運用手順（1件あたり）

  1. 端末のロックを解除し、アプリを起動して認証する
  2. 書類を枠内に収めて撮影する
  3. 項目ごとに読み取り結果を確認し、必要なら修正して「確認」を付ける
  4. 「Web入力へ進む」を押す
  5. 登録先の画面で内容を再確認し、自分で登録ボタンを押す
  6. 「終了して破棄」を押す。扱っていたデータは端末から消える

やってはいけないこと

  • 撮影画像・OCR結果・pcapをリポジトリへコミットする
  • 実在の個人情報をテストデータに使う
  • 監査ログに値を書き足す
  • 「一括登録が便利だから」と自動送信を実装する

トラブルシューティング

症状原因と対処
ブリッジが動かない（window.SLO が undefined） CSPがインラインスクリプトを止めている。ページのスクリプトを外部ファイルにする
取込元が見つからない 登録先ページを単体で開いている。OCRアプリのWebView内か、入居フォームから開く
引き渡しが E_EXPIRED で拒否される Envelopeの有効期限（既定5分）切れ。取込元でやり直す。端末の時刻ずれも確認する
引き渡しが E_VALIDATION で拒否される 値が正規形になっていない。取込元と登録先で共有コアの版が食い違っていないか確認する
引き渡しが E_ORIGIN で拒否される 登録先のオリジンが許可リストに無い。アプリ側の許可リストを確認する
verifyOfflineFlavorHasNoInternet が失敗する 依存ライブラリが権限を持ち込んでいる。src/offline/AndroidManifest.xml の tools:node="remove" を確認する
Gradleが :app を認識しない ANDROID_HOME が未設定。SDKが無い環境では意図的に :core だけ構成される
OCRの精度が出ない 明るさ・反射・傾きを変えて撮り直す。枠内に収める。それでも駄目なら手入力に切り替える
Secure Local OCR ／ 本書に登場する個人情報はすべて架空のものです。
