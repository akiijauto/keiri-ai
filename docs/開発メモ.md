# 開発メモ

## ポート割り当て（既存24サービスとの重複回避）

| サービス | ポート |
|---|---|
| Next.js (frontend) | 3100 |
| FastAPI (backend) | 8101 |

※ VPSに配置する前に `sudo ss -tlnp` で空きを確認すること。
重複していた場合は systemd ユニットと nginx 設定の両方を修正する。

当初 API は 8100 を予定していたが、実機調査（下記）で既存の gunicorn が
`127.0.0.1:8100` を使用中だったため 8101 に変更した。

## メモリ配慮

Xserver VPS は実測6GB（空き約3.9GB）。既存サービスと同居するため systemd で上限を設定する。

- API: MemoryMax=1G
- Web: MemoryMax=800M

`free -h` で余裕を確認してから起動すること。

## VPS実環境の調査結果（2026-08-09）

Xserver VPS「rakuya-lab」（220.158.27.233 / Ubuntu 24.04 LTS）に SSH で接続し、
情報取得のみのコマンドで確認した実測値。設計時の想定（4GB・API 8100）とずれていたため記録する。

### メモリ

| 項目 | 実測 |
|---|---|
| 合計 | 5.8Gi（カタログ値6GB） |
| 使用中 | 1.9Gi |
| 利用可能 | 3.9Gi |
| Swap | 2.0Gi（未使用） |

設計時は「4GB」と記載していたが実際は6GB。空き3.9GBあるため、
MemoryMax は API 1G / Web 800M まで緩和できると判断した。

### ディスク

`/dev/vda1` 145G 中 8.5G 使用（6%）、空き 136G。容量の制約はない。

### 導入済みソフトウェア

| ソフト | バージョン | 備考 |
|---|---|---|
| Node.js | v22.23.2 | Next.js のビルド・起動に十分 |
| Python | 3.12.3 | `python3-venv` で仮想環境を作る |
| nginx | 1.24.0 (Ubuntu) | 既存サイトと同居 |
| poppler-utils | `/usr/bin/pdftoppm` あり | PDF→画像変換。**追加インストール不要** |

`setup_vps.sh` の「1. 必要パッケージ」のうち poppler-utils と nginx は導入済み。

### ポート使用状況

| ポート | 状態 |
|---|---|
| 3100 | 空き → Next.js に割り当て |
| 8100 | **使用中**（gunicorn pid 839/732 が `127.0.0.1:8100` で LISTEN） |
| 8101 | 空き → FastAPI に割り当て |

8100 は既存アプリの gunicorn が localhost バインドで使用しており、
nginx のリバースプロキシ配下で動いている。keiri-ai の API は 8101 に変更した。

## AI呼び出しの切替

```bash
# .env
LLM_PROVIDER=gemini   # 既定（コスト抑制）
# LLM_PROVIDER=claude # クライアント案件でモデル指定がある場合
```

アプリ本体は `llm_client.get_client()` しか呼ばないため、
プロバイダ追加は `_PROVIDERS` にクラスを1つ足すだけで済む。
