# 開発メモ

## ポート割り当て（既存24サービスとの重複回避）

| サービス | ポート |
|---|---|
| Next.js (frontend) | 3100 |
| FastAPI (backend) | 8101 |

※ VPSに配置する前に `sudo ss -tlnp` で空きを確認すること。
重複していた場合は systemd ユニットと nginx 設定の両方を修正する。

当初 API は 8100 を予定していたが、実機調査（下記）で既存の gunicorn が
`127.0.0.1:8100` を使用中だったため 8101 に変更した。

## メモリ配慮

Xserver VPS は実測6GB（空き約3.9GB）。既存サービスと同居するため systemd で上限を設定する。

- API: MemoryMax=1G
- Web: MemoryMax=800M

`free -h` で余裕を確認してから起動すること。

## VPS実環境の調査結果（2026-08-09）

Xserver VPS「rakuya-lab」（220.158.27.233 / Ubuntu 24.04 LTS）に SSH で接続し、
情報取得のみのコマンドで確認した実測値。設計時の想定（4GB・API 8100）とずれていたため記録する。

| 項目 | 実測 |

### ポート使用状況

| ポート | 状態 |
|---|---|
| 3100 | 空き → Next.js に割り当て |
| 8100 | **使用中**（gunicorn pid 839/732 が `127.0.0.1:8100` で LISTEN） |

8100 は既存アプリの gunicorn が localhost バインドで使用しており、
nginx のリバースプロキシ配下で動いている。keiri-ai の API は 8101 に変更した。

## Next.js standalone構成での起動方法

`next.config.mjs` で `output: "standalone"` を指定しているため、
**`npm run start`（= `next start`）では起動できない**。Next.js 自身が警告を出す:

```
⚠ "next start" does not work with "output: standalone" configuration.
  Use "node .next/standalone/server.js" instead.
```

### 正しい起動手順

```bash
cd /opt/keiri-ai/app
npm install && npm run build

# standalone には静的ファイルが含まれないため手動でコピーする
cp -r .next/static .next/standalone/.next/
[ -d public ] && cp -r public .next/standalone/

# 起動（PORT / HOSTNAME は環境変数で渡す）
PORT=3100 HOSTNAME=127.0.0.1 node .next/standalone/server.js
```

`.next/static` のコピーを忘れるとページのHTMLは返るがCSS/JSが404になる。
ビルドし直すたびにコピーも実行すること。

### HOSTNAME を必ず指定する

standalone の `server.js` は `HOSTNAME` 未指定だと **`0.0.0.0`（全インターフェース）**
で待ち受ける。nginx の Basic認証を経由せず直接アクセスできてしまうため、
`HOSTNAME=127.0.0.1` を必ず指定する（systemd ユニットに設定済み）。

### 起動後は必ず待ち受けアドレスを検証する

```bash
ss -tlnp | grep -E '3100|8101'
# 期待: 127.0.0.1:3100 と 127.0.0.1:8101
# 0.0.0.0:xxxx や *:xxxx になっていたら設定が効いていない
```

## AI呼び出しの切替

```bash
# .env
LLM_PROVIDER=gemini   # 既定（コスト抑制）
# LLM_PROVIDER=claude # クライアント案件でモデル指定がある場合
```

アプリ本体は `llm_client.get_client()` しか呼ばないため、
プロバイダ追加は `_PROVIDERS` にクラスを1つ足すだけで済む。
